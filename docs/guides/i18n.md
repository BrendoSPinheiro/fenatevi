# Internacionalização (next-intl)

Leia antes de: escrever qualquer texto visível, criar rota ou mexer em idioma.

## Configuração (fato)

- Idiomas: `pt-BR` (padrão, sem prefixo, em `/`), `en` (`/en`), `es` (`/es`) —
  estratégia `localePrefix: 'as-needed'`.
- Fonte da verdade: [`src/lib/i18n/routing.ts`](../../src/lib/i18n/routing.ts)
  (`locales`, `defaultLocale`, `localeLabels`, `localeHtmlLang`).
- Configuração por requisição em `src/lib/i18n/request.ts`, registrada pelo
  plugin no `next.config.ts`; `timeZone: 'America/Sao_Paulo'`.
- O idioma preferido é detectado a partir do `Accept-Language` em `src/proxy.ts`.
- O segmento `[locale]` é sempre validado com `hasLocale` antes do uso.

## Regras

- **Nenhum texto visível ao usuário pode ser escrito no JSX.** Tudo vem de
  `messages/`.
- Ao adicionar uma chave, adicione-a nos **três** arquivos (`pt-BR`, `en`, `es`).
  Uma chave faltando é erro em produção.
- Consuma com `getTranslations('namespace')` (servidor) ou
  `useTranslations('namespace')` (cliente).
- Valores dinâmicos por interpolação (`t('dates', { start, end })`), nunca por
  concatenação de strings.
- Datas: use `formatFestivalDate` de `src/lib/utils/format.ts` — formata em UTC
  de propósito, para que o fuso do servidor não desloque o dia exibido.
- Navegação ciente de idioma: `Link`, `useRouter`, `usePathname`, `redirect` e
  `getPathname` vêm de `@/lib/i18n/navigation`, nunca de `next/link` ou
  `next/navigation`.
- Para adicionar um idioma inteiro, siga o passo a passo do
  [`README.md`](../../README.md): os `Record<Locale, string>` fazem o
  `pnpm typecheck` acusar qualquer omissão. Alterar a estratégia de i18n
  (`localePrefix`, `defaultLocale`, lista de idiomas) exige autorização humana.
